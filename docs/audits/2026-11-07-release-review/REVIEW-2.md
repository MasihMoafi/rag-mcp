## Verdict

**The CLI and MCP server are not ready to publish.** A failed reconnect can discard registration settings, including an allowed-root restriction; rotating an OpenRouter key can leave embeddings using the old key; and the release workflow does not depend on the quality or artifact-smoke workflows. These are release risks even though the branch adds useful checks. [Reconnect](../../../rag/cli_agents.py:125), [key selection](../../../rag/embeddings.py:330), [release workflow](../../../.github/workflows/release.yml:14).

**The sampled engineering is not yet on par with DeepSeek harness.** rag-mcp now defines keyless Python, lint, and strict-type lanes, but strict typing covers only three modules, excluding the MCP server. The reference validates protocol models and makes installed-wheel compatibility checks dependencies of release validation. [rag-mcp typing](../../../pyrightconfig.json:2), [reference models](deepseek-harness/python/sdk/src/deepseek_harness/models.py:26), [reference release](deepseek-harness/.github/workflows/python-release.yml:68).

## New problems, ranked

1. **P1 — Failed reconnect can remove restrictions.** Codex restoration reconstructs only command and arguments; Claude restoration likewise keeps only type, command, and arguments. A restored entry can therefore lose environment settings such as `RAG_MCP_ALLOWED_ROOTS`. The fake-client test stores no environment to catch this. Preserve the complete entry and test failed replacement and failed restoration. [cli_agents.py](../../../rag/cli_agents.py:73), [reconnect test](../../../tests/unit/test_reconnect_safety.py:21).
2. **P1 — Key rotation and removal disagree across stages.** With a legacy OpenRouter embedding key, `rag key set` makes synthesis use the new key while embeddings prefer the old one. `rag key remove` clears only the new field, so the legacy saved key can remain active. Migrate or consistently resolve both fields and test rotation/removal. [embeddings.py](../../../rag/embeddings.py:334), [openrouter_pipeline.py](../../../rag/openrouter_pipeline.py:81), [keys.py](../../../rag/keys.py:77).
3. **P1 — Publication can proceed without passing quality checks.** The tag workflow’s publish jobs depend on its build, which checks metadata and hashes; it does not depend on the separate test, type, lint, or installed-artifact jobs. Make those checks dependencies of publication. Repository environment protection was **not checked**. [release.yml](../../../.github/workflows/release.yml:14), [quality workflow](../../../.github/workflows/python-quality.yml:10).
4. **P2 — The new saved key is missed by setup and capability reporting.** `rag config embedding` can reject an OpenRouter model when only the dedicated key is saved; the interactive picker can ask for it again, and capabilities can report embedding unavailable. Use one credential resolver across these paths. [cli.py](../../../rag/cli.py:137), [setup_ui.py](../../../rag/setup_ui.py:130), [control.py](../../../rag/control.py:109).
5. **P2 — Acceptance coverage was reduced.** The previous artifact smoke covered mocked provider setup, npx/pnpm, and missing-uv handling; the replacement omits them. Also, module-level Qdrant skips now skip LanceDB cases when the optional Qdrant dependency is absent. Restore the useful artifact cases and skip only Qdrant cases. [previous smoke](../../../tests/install/smoke.sh:51), [current smoke](../../../tests/install/smoke.sh:17), [backend tests](../../../tests/unit/test_backend_contract.py:6).
6. **P3 — Warm scope checks add Git processes.** Clearing the cache makes an unchanged cached scope recheck each visited nonempty directory with `git check-ignore`. Measure warm scans and invalidate using ignore-rule changes without repeating every subprocess. Timing was **not checked**. [server.py](../../../rag/server.py:85), [Git check](../../../rag/server.py:552).

1. **Release evidence:** Gate publication on tests of the exact wheel and npm package, including an MCP tool call through the installed entry point. The reference makes installed SDK and MCP scenarios dependencies of release validation. [rag-mcp release](../../../.github/workflows/release.yml:30), [reference release](deepseek-harness/.github/workflows/python-release.yml:68).
2. **Platform coverage:** Test the claimed supported platforms and Python versions, or narrow the package claims. rag-mcp’s new quality matrix is Linux-only; the reference defines Linux, macOS, and Windows release targets. [rag-mcp metadata](../../../pyproject.toml:7), [quality matrix](../../../.github/workflows/python-quality.yml:11), [reference targets](deepseek-harness/.github/workflows/python-release.yml:25).
3. **Protocol boundaries:** Validate each MCP tool’s request and response with typed models and include the server in strict checking. Its new wrapper still accepts `dict[str, Any]`; the reference has validated protocol models. [rag server](../../../rag/server.py:55), [reference models](deepseek-harness/python/sdk/src/deepseek_harness/models.py:35).

[rag trust boundary](../../../README.md:374), [reference scope test](deepseek-harness/packages/mcp/mcp-resources/tests/resources.spec.ts:167).

[rag server](../../../rag/server.py:718), [reference errors](deepseek-harness/python/sdk/src/deepseek_harness/errors.py:4).
